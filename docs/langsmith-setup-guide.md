# LangSmith Setup and Testing Guide

This guide walks you through setting up and testing LangSmith traceability in the Construction Specification Assistant.

## Prerequisites

- Backend application running
- Access to LangSmith (https://smith.langchain.com/)

---

## Step 1: Get LangSmith API Key

1. **Sign up for LangSmith**:
   - Go to https://smith.langchain.com/
   - Create an account (free tier available)

2. **Create a Project**:
   - Click "New Project"
   - Name it `construction-spec-assistant` (or your preferred name)

3. **Generate API Key**:
   - Go to Settings → API Keys
   - Click "Create API Key"
   - Copy the API key (you won't be able to see it again!)

---

## Step 2: Configure Environment Variables

### Option A: Using .env file (Recommended for Development)

1. **Edit your `.env` file** in the `backend/` directory:

```bash
# LangSmith Configuration
LANGSMITH_ENABLED=true
LANGSMITH_API_KEY=lsv2_pt_your-actual-api-key-here
LANGSMITH_PROJECT=construction-spec-assistant
LANGSMITH_ENDPOINT=https://api.smith.langchain.com
LANGSMITH_TRACING_V2=true
```

2. **Save the file**

### Option B: Using Environment Variables (Production)

```bash
export LANGSMITH_ENABLED=true
export LANGSMITH_API_KEY=lsv2_pt_your-actual-api-key-here
export LANGSMITH_PROJECT=construction-spec-assistant
export LANGSMITH_ENDPOINT=https://api.smith.langchain.com
export LANGSMITH_TRACING_V2=true
```

---

## Step 3: Start the Backend

1. **Start the backend server**:

```bash
cd backend
uv run uvicorn app.main:app --reload
```

2. **Check the startup logs** - you should see:

```
============================================================
LangSmith Tracing Enabled
  Project: construction-spec-assistant
  Endpoint: https://api.smith.langchain.com
  Tracing V2: True
============================================================
```

If you see this, LangSmith is successfully initialized! 🎉

---

## Step 4: Test Fact Extraction Tracing

### Test 1: Upload and Process a Document

1. **Upload a specification document** via the frontend or API:

```bash
curl -X POST "http://localhost:8000/api/v1/documents/upload" \
  -F "file=@path/to/your/spec.pdf" \
  -F "document_type=specification"
```

2. **Trigger fact extraction**:

```bash
curl -X POST "http://localhost:8000/api/v1/documents/{document_id}/extract-facts"
```

3. **Check LangSmith Dashboard**:
   - Go to https://smith.langchain.com/
   - Navigate to your project
   - You should see traces for each chunk processed
   - Each trace will have tags: `fact-extraction`, `doc:{id}`, `chunk:{id}`, `section:{id}`

### What to Look For

In the LangSmith dashboard, you should see:

- **Run Name**: Automatically generated by LangChain
- **Tags**: `fact-extraction`, `doc:xxx`, `chunk:xxx`, `section:xxx`
- **Metadata**:
  - `operation`: "fact_extraction"
  - `document_id`: Document UUID
  - `chunk_id`: Chunk UUID
  - `section_id`: Section identifier
  - `section_title`: Section title
  - `entity_hint`: Entity hint (if provided)
  - `temperature`: LLM temperature
  - `chunk_length`: Length of chunk content
- **Input**: System prompt + user prompt with chunk text
- **Output**: JSONL with extracted facts
- **Token Usage**: Input/output tokens
- **Latency**: Time taken for LLM call

## Step 5: Test Comparison Agent Tracing

### Test 2: Run a Comparison

1. **Upload a submittal document**:

```bash
curl -X POST "http://localhost:8000/api/v1/documents/upload" \
  -F "file=@path/to/your/submittal.pdf" \
  -F "document_type=submittal"
```

2. **Start a comparison job**:

```bash
curl -X POST "http://localhost:8000/api/v1/comparison/compare" \
  -H "Content-Type: application/json" \
  -d '{
    "spec_document_id": "your-spec-doc-id",
    "submittal_document_id": "your-submittal-doc-id"
  }'
```

3. **Check LangSmith Dashboard**:
   - You should see traces for each comparison
   - Each trace will have tags: `comparison-agent`, `spec:{fact_id}`, `verdict-check`

### What to Look For

In the LangSmith dashboard, you should see:

- **Run Name**: Automatically generated by LangChain
- **Tags**: `comparison-agent`, `spec:xxx`, `verdict-check`
- **Metadata**:
  - `operation`: "spec_comparison"
  - `spec_fact_id`: Fact UUID
  - `entity_type`: Entity type from spec
  - `entity_name`: Entity name from spec
  - `attribute`: Attribute being compared
  - `operator`: Comparison operator (=, >=, etc.)
  - `expected_value`: Expected value from spec
  - `num_retrieved_chunks`: Number of chunks retrieved
  - `avg_relevance_score`: Average relevance score
- **Input**: System prompt + comparison prompt with context
- **Output**: JSON with verdict, confidence, evidence, reasoning
- **Token Usage**: Input/output tokens
- **Latency**: Time taken for LLM call

## Step 6: Explore LangSmith Features

### Filtering Traces

Use tags to filter traces:

- **All fact extractions**: Filter by tag `fact-extraction`
- **Specific document**: Filter by tag `doc:{document_id}`
- **All comparisons**: Filter by tag `comparison-agent`
- **Specific spec fact**: Filter by tag `spec:{fact_id}`

### Analyzing Performance

1. **View Token Usage**:
   - See total tokens used per operation
   - Estimate costs based on your LLM provider

2. **View Latency**:
   - Identify slow operations
   - Optimize prompts or retrieval strategies

3. **View Success/Failure Rates**:
   - Track errors and exceptions
   - Debug failed LLM calls

### Comparing Runs

1. **Select multiple traces**
2. **Click "Compare"**
3. **View side-by-side comparison** of:
   - Inputs (prompts)
   - Outputs (responses)
   - Token usage
   - Latency

## Troubleshooting

### Issue: No traces appearing in LangSmith

**Check 1**: Verify environment variables are set correctly

```bash
# In your backend directory
uv run python -c "from app.config import settings; print(f'Enabled: {settings.langsmith_enabled}'); print(f'API Key: {settings.langsmith_api_key[:10]}...' if settings.langsmith_api_key else 'API Key: None')"
```

**Check 2**: Verify startup logs show LangSmith initialization

Look for the "LangSmith Tracing Enabled" banner in the logs.

**Check 3**: Verify API key is valid

- Go to LangSmith dashboard
- Check API Keys section
- Ensure the key hasn't been revoked

### Issue: Traces appear but metadata is missing

**Solution**: Ensure you're using the latest code with RunnableConfig

The metadata is added via `RunnableConfig` in:
- `backend/app/services/fact_extraction.py` (line ~152)
- `backend/app/agents/comparison_graph.py` (line ~149)

### Issue: Too many traces / high costs

**Solution**: Disable tracing in development

```bash
# In .env file
LANGSMITH_ENABLED=false
```

Or use sampling (future enhancement).

## Best Practices

### 1. Use Different Projects for Different Environments

```bash
# Development
LANGSMITH_PROJECT=construction-spec-assistant-dev

# Staging
LANGSMITH_PROJECT=construction-spec-assistant-staging

# Production
LANGSMITH_PROJECT=construction-spec-assistant-prod
```

### 2. Monitor Token Usage

- Set up alerts in LangSmith for high token usage
- Review traces regularly to optimize prompts

### 3. Use Tags for Organization

- Tags make it easy to filter and analyze traces
- Current tags are automatically added by the code

### 4. Review Failed Traces

- Failed traces help identify issues with prompts or LLM responses
- Use the error messages to improve error handling

### 5. Compare Different Prompts

- Use LangSmith's comparison feature to A/B test prompts
- Track which prompts produce better results
